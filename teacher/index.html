Student-ready: one complete 5-day unit. The requested nine-week course is not complete. This release deliberately implements and tests the first unit; the other 40 days are specified in the tracker. Do not assign future tracker entries as lessons.

What students need

A Chromebook or other browser device and one 40-minute period daily. No installations, physical materials, research, microphones, sign-in, or external media are needed for the unit. Core files load from this site only. The personal typing task uses the student's actual device; comparison cards and troubleshooting controls are explicitly fictional. Teach that distinction.

Prepare and distribute

  1. Follow the repository README to open locally or publish the static files on GitHub Pages. There is no server-side code. This package is not already published to a live URL.
  2. Test your chosen URL from a managed student Chromebook. School filtering and download policies vary; confirm before assigning.
  3. In Google Classroom, create an assignment for each day. Paste the site URL with its day hash, such as YOUR-PUBLISHED-URL/#lesson-1. State whether students should attach the downloaded text file or paste the “Show work to copy” text into their response. The site cannot submit to Classroom.
  4. Tell students that closing, refreshing, or opening a new tab clears work. Navigation between days inside the open tab preserves entries. Have students export at the end of the period and again after revisions. If downloads are blocked, use the copy box. No recovery of unsaved work is promised.
  5. Preview the answer keys and project checklist. Practice-friendly feedback reveals the reasoning. Use the separate PDF if you need an independent knowledge check.

Support and extension

For students who need support, read one section aloud, have them restate the term, demonstrate one step, then let them repeat it. Use the supplied sentence starters. Pair verbal discussion is optional and needs no materials. Keep typed work individual when collecting device evidence. At 200% zoom the layout reflows; controls use native keyboard behavior. Feedback uses text and live status regions as well as color. Shorten the written response with teacher-guided dictation into the response field if necessary; do not require browser speech services.

For faster students, ask them to explain why a tempting wrong answer fails using the on-site facts, or improve the clarity of their help message. Do not add untaught research questions. Pacing is designed, not classroom-pilot validated; if reading takes longer, use the next period for written evidence rather than removing the hands-on evaluation.

Written performance tasks remain in the website and rubric; they are not replaced by multiple-choice items.

Reteach from the evidence

  • Device conclusions too broad: return to Day 1 reading 4 and require a “did not test” sentence.
  • Hardware/software confusion: return to Day 2 reading 1; ask which physical part and which instructions are both required.
  • Cause guessed without tests: return to Day 3 readings 1–3; require the two observed check results before a solution.
  • No verification: have students repeat Send sample after resuming and add the outcome to the message.

Technical and verification limits

No student account, cookies, localStorage, analytics, web fonts, external scripts, or network requests from core tasks. Work remains in DOM memory until refresh. All data and answers are inspectable in a static site. This is not a secure testing platform. Automated checks exercise keys, state rules, links, citations, and interactions; a human must still assess written reasoning and classroom suitability. See the test report shipped with this release for actual results and limitations.
